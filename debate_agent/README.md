# AI Debate Judge

의견이 갈리는 질문을 여러 AI 에이전트가 **논증 → 독립 검증 → 판정**의 3단계로 분석하는
LangGraph 멀티 에이전트 웹 애플리케이션입니다.

핵심은 "누가 더 말을 잘했는가"가 아니라 **"누가 더 합리적이고 타당한 논리를 제시했는가"** 를
판단하는 것입니다. 이를 위해 찬반 에이전트의 논증을 **서로를 모르는 독립적인 검증 에이전트**가
각각 따로 검증하고, 최종 사회자는 그 검증 결과를 근거로 판정합니다.

판정에는 **반드시 승자가 나옵니다.** 무승부는 없습니다. 대신 승부가 얼마나 갈렸는지를
**우세 격차(신승 / 우세승 / 완승 / 압승)** 로 함께 보여주어, 근소한 승리를 압승처럼
보이게 만들지 않습니다.

진영 이름은 질문에 맞춰 자동으로 정해집니다. 찬반형 질문이면 "찬성 / 반대",
선택지를 비교하는 질문이면 그 선택지 이름이 그대로 쓰여, 무엇이 이겼는지 바로 보입니다.

```
질문: 청년피자와 처갓집 슈프림양념치킨 중에 뭐가 더 나을까?

        FINAL VERDICT
        처갓집 치킨 승리   [신승]

        처갓집 치킨 55 ████████████░░░░░░░░ 45 청년피자
```

## 처음 받았다면 (git clone 직후)

`.env` 는 API 키가 들어 있어 **깃에 올라가지 않습니다.** 클론하면 이 파일이 없으므로
직접 만들어야 합니다. 이 한 단계만 하면 나머지는 자동입니다.

**1. 저장소 루트에 `.env` 파일을 만들고 키를 적습니다.**

```
OPENAI_API_KEY=sk-...
```

위치는 저장소 루트(`debate_agent` 의 상위 폴더) 또는 `debate_agent` 안, 둘 중 아무 곳이나 됩니다.

**2. `debate_agent\run.bat` 을 더블클릭합니다.**

가상환경 생성과 패키지 설치를 알아서 합니다 (약 30초~몇 분, 인터넷 속도에 따라 다름).

```
  ==========================================
    AI Debate Judge
  ==========================================

  처음 실행입니다. 실행 환경을 준비합니다...
  [1/2] 가상환경 생성 중...
  [2/2] 필요한 패키지 설치 중...

  준비 완료!
```

끝나면 브라우저가 자동으로 열립니다 → **http://localhost:8501**

`.env` 를 빼먹으면 아래처럼 알려주고 멈추므로, 원인을 몰라 헤맬 일은 없습니다.

```
  [오류] .env 파일을 찾을 수 없습니다.

  아래 위치 중 한 곳에 .env 파일을 만들고
  OPENAI_API_KEY=sk-... 를 적어 주세요.
```

> **필요한 것은 Python 3.10 이상뿐입니다.** 없으면 run.bat 이 설치 링크를 안내합니다.
> (설치할 때 "Add Python to PATH" 를 체크해야 합니다.)

## 이후 실행

**`run.bat` 더블클릭.** 두 번째부터는 준비 단계 없이 바로 뜹니다.

- 이미 실행 중이면 브라우저만 새로 엽니다
- 종료하려면 검은 서버 창에서 `Ctrl + C` 를 누르거나 창을 닫습니다

### VS Code 에서 실행하려면

`.vscode/tasks.json` 과 `launch.json` 이 준비되어 있습니다.

| 방법 | 동작 |
|---|---|
| **`Ctrl+Shift+B`** | 웹앱 실행 (가장 빠름) |
| `Ctrl+Shift+P` → `Tasks: Run Task` | 실행 / 테스트 / CLI 분석 중 선택 |
| `F5` | 디버거를 붙여 실행 (중단점 사용) |
| `Ctrl+Shift+P` → `Simple Browser: Show` | **VS Code 안에서** 웹앱 보기 |

터미널에서 직접 쓸 수도 있습니다.

```powershell
cd C:\Workspace\APPS\debate_agent
.\run.ps1                 # 웹앱 실행
.\run.ps1 -Test           # 시스템 테스트 (LLM 호출 없음)
.\run.ps1 -Ask "질문"     # 터미널에서 한 번만 분석
```

Streamlit 을 직접 띄우려면 아래처럼 합니다. 이 경우 브라우저는 자동으로 열리지 않으므로
http://localhost:8501 로 직접 접속하세요. (최초 실행 시 Streamlit 이 이메일을 묻지 않도록
`.streamlit/config.toml` 에서 `headless = true` 로 두었고, 브라우저 자동 열기는
`run.ps1` 이 담당하기 때문입니다.)

```powershell
..\.venv\Scripts\streamlit.exe run app.py
```

### 런처가 두 파일인 이유

`run.bat` 은 ASCII 전용이고 실제 로직은 `run.ps1` 에 있습니다.
cmd.exe 는 배치 파일을 OEM 코드페이지로 파싱하기 때문에 `.bat` 안에 한글을 넣으면
줄이 깨져 명령이 쪼개집니다(UTF-8 BOM 을 붙여도 마찬가지). 그래서 한글 메시지는
UTF-8 을 제대로 처리하는 PowerShell 쪽에 두었습니다.

### 환경변수

`.env` 는 이 폴더 또는 상위 폴더(`C:\Workspace\APPS\.env`)에서 자동으로 탐색합니다.

| 변수 | 기본값 | 설명 |
|---|---|---|
| `OPENAI_API_KEY` | (필수) | OpenAI API 키 |
| `OPENAI_MODEL` | `gpt-4o-mini` | 전체 에이전트가 사용할 모델 |
| `OPENAI_JUDGE_MODEL` | `OPENAI_MODEL` 값 | 최종 판정만 다른 모델로 돌리고 싶을 때 |
| `OPENAI_TEMPERATURE` | `0.4` | 추론 모델(gpt-5 계열)에서는 자동으로 무시됩니다 |
| `STRUCTURED_OUTPUT_RETRIES` | `2` | 구조화 출력 파싱 실패 시 재시도 횟수 |
| `OPENAI_MAX_RETRIES` | `3` | API 오류·rate limit 백오프 재시도 |
| `LOG_LEVEL` | `INFO` | 노드 실행 로그 상세도 |

모델명은 코드에 하드코딩되어 있지 않으므로 `.env` 만 고치면 교체됩니다.

```bash
OPENAI_MODEL=gpt-5-mini
```

## 아키텍처

```
                        START
                          │
                  ┌───────▼────────┐
                  │   Moderator    │  쟁점 분석 · 질문 유형 분류 · 입장 배정
                  └───────┬────────┘
              ┌───────────┴───────────┐      ← 병렬 (같은 superstep)
              ▼                       ▼
      ┌───────────────┐       ┌───────────────┐
      │   PRO Agent   │       │   CON Agent   │  각자 독립적으로 논증 생성
      └───────┬───────┘       └───────┬───────┘
              ▼                       ▼          ← 병렬
      ┌───────────────┐       ┌───────────────┐
      │  PRO Critic   │       │  CON Critic   │  자기 진영 논증만 보고 검증
      └───────┬───────┘       └───────┬───────┘
              └───────────┬───────────┘          ← join (양쪽 완료 후 1회)
                          ▼
                  ┌───────────────┐
                  │Final Moderator│  검증 결과를 근거로 판정
                  └───────┬───────┘
                          ▼
                         END
```

LangGraph 는 같은 superstep 의 노드를 동시에 실행하므로 진영별 체인이 실제로 병렬로 돕니다.
LLM 호출은 총 6회이며, 실측 기준 순차 실행 대비 **약 1.4배** 빠릅니다.

## 이 시스템이 지키는 설계 원칙

### 1. 정보 격리 — 프롬프트가 아니라 코드로 강제

`PRO Critic` 은 `state["arguments"]["PRO"]` 만 꺼내 프롬프트를 만듭니다.
상대 진영의 논증은 프롬프트 빌더에 **전달조차 되지 않으므로**, 검증자가 상대 주장을 근거로
판단하는 일이 구조적으로 불가능합니다. ([agents/critic.py](agents/critic.py))

이 불변식은 테스트로 보호됩니다 — 각 진영 논증에 고유 표식을 심고, 상대 표식이
검증 프롬프트에 새어 들어가지 않는지 확인합니다.

### 2. 편향 방지

| 편향 | 차단 방식 |
|---|---|
| 위치 편향 | 최종 판정 프롬프트의 진영 순서를 매 실행마다 무작위 셔플 |
| 길이 편향 | 논거 개수 상한(`MAX_ARGUMENTS_PER_SIDE`)을 모든 진영에 동일 적용 |
| 점수 편향 | `FinalJudgment` 스키마에 점수 합계 필드가 없음. 점수는 참고 지표로만 전달 |
| 상호 오염 | 한 진영 평가에 상대 주장을 쓰지 못하도록 정보 격리 + 프롬프트 명시 |
| 억지 승자 | 질문 유형별로 판정 지침을 분기. 주관적 질문은 무승부를 우선 검토 |

### 3. 승자는 반드시 나오되, 격차로 정직하게 말한다

`verdict` 스키마에는 진영 ID 두 개뿐이며 무승부·판단 유보 값이 **아예 존재하지 않습니다.**
모델이 어떤 이유로든 다른 값을 내놓아도 검증 점수 합계가 높은 쪽으로 보정되어 승자가 나옵니다.

억지 승자의 위험은 **불확실성을 다른 곳으로 옮겨** 관리합니다.

| 표현 수단 | 역할 |
|---|---|
| `margin_level` / `margin_score` | 얼마나 근소한 승부였는지 (51~95) |
| `confidence` | 판정 자체에 대한 확신도 |
| `limitations` | 이 판정이 놓치고 있는 것 |

| 격차 등급 | 표기 | 범위 | 의미 |
|---|---|---|---|
| `NARROW` | 신승 | 51~57 | 사실상 대등. 반대 결론도 가능 |
| `CLEAR` | 우세승 | 58~68 | 분명히 앞서지만 패한 쪽에도 유효한 논거 |
| `DECISIVE` | 완승 | 69~82 | 핵심 쟁점에서 승부가 갈림 |
| `OVERWHELMING` | 압승 | 83~95 | 패한 쪽에 사실 오류나 치명적 결함 |

등급과 수치가 어긋나면 등급 기준으로 수치를 보정하므로, 화면의 게이지와 배지는 항상 일치합니다.

사회자는 질문 유형에 따라 **무엇을 기준으로 우열을 가릴지**를 바꿉니다.

| 유형 | 예시 | 판정 기준 |
|---|---|---|
| `OBJECTIVE` | "SSD와 HDD 중 랜덤 읽기가 빠른 것은?" | 사실적 정확성. 사실 오류가 있으면 격차를 크게 |
| `SUBJECTIVE` | "짜장면과 짬뽕 중 뭐가 더 맛있어?" | 취향의 우열이 아니라 **입장을 얼마나 논리적으로 방어했는가**. 격차는 대개 NARROW/CLEAR |
| `MIXED` | "재택근무가 출근보다 생산적인가?" | 조건별로 따진 뒤 종합. 조건에 따라 갈릴수록 격차를 낮게 |
| `NORMATIVE` | "대학 등록금은 낮춰야 하는가?" | 가치관의 승패가 아니라 **논증 수행의 승패** |

주관적·규범적 질문에서는 "이 질문은 본래 취향/가치의 문제이며 승패가 선호의 우열을 뜻하지
않는다"는 문장이 `limitations` 에 반드시 들어갑니다.

### 3-0. 진영 이름은 질문이 정한다

`PRO` / `CON` 은 상태 키와 스키마에만 쓰이는 내부 ID 이고, 화면에 나오는 이름은
사회자가 질문을 보고 붙입니다. (`PositionSpec.label`)

| 질문 형태 | 예시 | 표시 라벨 |
|---|---|---|
| 찬반형 | "대학 등록금은 낮춰야 하는가?" | 찬성 측 / 반대 측 |
| 선택지 비교형 | "청년피자와 처갓집 치킨 중 뭐가 나을까?" | 청년피자 / 처갓집 치킨 |
| 양자택일형 | "운동은 아침에? 밤에?" | 아침 운동 / 저녁 운동 |
| 객관 비교형 | "SSD와 HDD 중 랜덤 읽기가 빠른 것은?" | SSD / HDD |

라벨은 판정 카드·진영 카드·점수 막대·진행 표시까지 한 번에 적용되고, LLM 이 서술문에
내부 ID 를 흘리면 표시 직전에 라벨로 치환됩니다(한국어 조사도 함께 보정 —
`PRO는` → `청년피자는`, `찬성은`). '찬성'처럼 일반적인 라벨에만 "측"을 붙이고,
'청년피자' 같은 고유명은 그대로 씁니다.

중복되거나 비어 있는 라벨은 기본값(찬성/반대)으로 되돌아갑니다.

### 3-1. 점수와 판정이 엇갈리면 그 사실을 알린다

이 시스템은 점수 합계로 승자를 정하지 않으므로, 검증 점수 총합이 높은 쪽이 질 수 있습니다.
그런 역전이 일어나면 결과 화면이 이를 **숨기지 않고 별도 카드로 표시**합니다.

> 검증 점수 합계는 **반대 측**이 높지만(70점 만점 · 반대 34점 / 찬성 30점),
> 사회자는 **찬성 측**을 승자로 판정했습니다.

### 3-2. 판정에 실패하면 승자를 지어내지 않는다

판정 에이전트가 오류로 응답하지 못한 경우에는 임의의 승자를 만들지 않고 판정을 비워 둡니다.
결과 화면은 "판정 실패"를 명시하고 양측 논증과 검증 결과만 보여줍니다.

### 4. 환각 방지

모든 논거는 `evidence_status` 를 반드시 표기합니다.

- `VERIFIABLE_FACT` — 외부 자료로 검증 가능
- `COMMON_KNOWLEDGE` — 널리 통용되는 상식
- `VALUE_JUDGMENT` — 가치판단 (참/거짓 대상 아님)
- `UNVERIFIED` — 근거를 댈 수 없는 주장

존재하지 않는 통계·논문을 지어내는 대신 상태를 표시하게 만들고, 검증자는 `UNVERIFIED` 를
자동으로 점검 대상에 올립니다. 검증자에게는 검색 도구가 없으므로, 확인 불가능한 주장을
**거짓으로 단정하지 않고** "외부 자료 확인 필요"로 표시합니다.

### 5. 판정 근거와 한계를 분리

결과 화면은 "왜 이 결론에 이르렀는가"와 "다만 이 판단에도 한계가 있습니다"를
항상 나란히 보여줍니다. 승자가 있는 경우에도 **이긴 쪽 논리에 남아 있는 문제를 최소 1개**
포함하도록 프롬프트에서 요구합니다.

## 프로젝트 구조

```
debate_agent/
├── run.bat                 # 더블클릭 실행 (ASCII 전용 런처)

│
├── agents/
│   ├── base.py             # safe_node 데코레이터, 진영 ID 정규화
│   ├── moderator.py        # 1차 사회자 (쟁점 분석)
```

`debate_NEUTRAL` / `critic_NEUTRAL` 노드가 생성되고, 결과 화면도 3컬럼이 됩니다.

## 오류 처리

에이전트 하나가 실패해도 전체가 중단되지 않습니다.

- **구조화 출력 파싱 실패** → 실패 사유를 덧붙여 재요청 (기본 2회)
- **노드 실패** → `safe_node` 가 예외를 상태로 흡수하고 폴백 결과를 넣어 그래프 진행
- **판정 실패** → 승자를 지어내지 않고 판정을 비운 뒤, 양측 논증·검증 결과만 표시
- **API 키 없음** → 앱 시작 시 안내 메시지 후 중단
- **rate limit / 네트워크 오류** → OpenAI SDK 백오프에 위임

실패가 발생하면 결과 화면 상단에 어떤 에이전트가 실패했는지 경고 배너로 표시됩니다.

## 알아두실 점

- 결과는 AI 에이전트가 생성한 분석이며 확정적 사실이나 정답이 아닙니다.
- 이 시스템은 설계상 **항상 승자를 냅니다.** 승패보다 우세 격차와 판정 근거를 함께 보셔야
  합니다. 특히 주관적 질문에서 "신승"은 사실상 우열을 가리기 어려웠다는 뜻입니다.
- 검증 점수는 각 논증을 독립 평가한 AI 의 **보조 지표**이며 객관적 측정값이 아닙니다.
  최종 판정은 점수 합계가 아니라 논증의 내용으로 결정됩니다.
- 분석 1회당 LLM 호출 6회가 발생합니다 (`gpt-4o-mini` 기준 수 원 수준).
